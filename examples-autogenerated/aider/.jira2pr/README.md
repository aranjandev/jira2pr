# jira2pr — Aider Setup Guide

> This file lives at `.jira2pr/README.md` and documents the agent framework
> installed in your project. Keep it here so any developer can understand what's
> available and how to use it.

## What Was Installed

`.jira2pr/` contains everything the `jira2pr` runtime engine needs to drive
[aider](https://aider.chat) through the same feature workflow used by the
Copilot setup: read a JIRA ticket → plan → implement → self-review → submit a
Pull Request. Agent behavior lives in `.jira2pr/agents/*.md` (used as
system prompts); workflow state machines live in `.jira2pr/workflows/`;
model selection lives in `.jira2pr/config/aider.yaml`. All of it is
generated by `jira2pr` from canonical definitions — do not edit generated
files by hand. Re-run `jira2pr init --platform aider` to pick up upstream
changes (stale files are pruned automatically).

Unlike Copilot, Aider has no native multi-agent orchestration, so the
`jira2pr` package (installed via `pip`/`uv`) supplies the workflow executor
that shells out to `aider` once per worker step.

## Prerequisites

- **Python 3.10+**
- **aider** installed and on `PATH` (`pip install aider-chat` or `uv tool install aider-chat`)
- **jira2pr** installed (`uv tool install jira2pr`)
- **git** configured with push access to your repo
- An API key for whichever model provider you configure in
  `.jira2pr/config/aider.yaml` (see [aider's model docs](https://aider.chat/docs/llms.html))

## Setup

### 1. Set environment variables

```bash
cp .env.example .env
```

Fill in `JIRA_BASE_URL`, `JIRA_EMAIL`, `JIRA_API_TOKEN`, and either
`GITHUB_TOKEN` or `BITBUCKET_TOKEN`/`BITBUCKET_USERNAME`, plus whatever API
key your chosen model provider requires (e.g. `ANTHROPIC_API_KEY`).

### 2. Pick your models

Edit `.jira2pr/config/aider.yaml` — the `models` map uses provider-agnostic
defaults; point each tier at whichever model/provider you have access to.

## Usage

```bash
jira2pr run feature PROJ-123
```

Resume an interrupted workflow:

```bash
jira2pr resume PROJ-123
```

Check status without executing anything:

```bash
jira2pr status PROJ-123
```

List in-progress workflows:

```bash
jira2pr list
```

## Directory Structure

```
.jira2pr/
├── README.md              # This file
├── config.yaml            # Resolved platform + model config
├── config/
│   └── aider.yaml          # Tier → aider model map, CLI flags
├── capabilities.yaml       # Capability → runtime binding map
├── workflows/              # Workflow state machines (feature, ...)
├── artifacts/               # Artifact schemas (plan-schema.md, ...)
├── agents/                  # Agent bodies (system prompts)
└── state/                    # Workflow state instances (created at runtime)

.aider.conf.yml             # Default aider CLI config (jira2pr overrides --model per call)
.aiderignore                # Keeps aider from touching workflow state
```
